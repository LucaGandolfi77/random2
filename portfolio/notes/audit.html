The audit that found its own bug L'audit che ha trovato un suo bug

I wrote a tool to check this repository's accessibility. The first thing it found was a crash that had been there from the start. Ho scritto uno strumento per verificare l'accessibilità di questo repository. La prima cosa che ha trovato è stato un errore che c'era fin dall'inizio.

4 minutes · tools/audit 4 minuti · tools/audit

The rule in this repository is that a claim is only true if a machine says so. The portfolio's numbers are recomputed from the repository by tools/verify.mjs and CI fails if one of them drifts. That is a lot of machinery for a page, and it is easy to think the machinery is the point. La regola di questo repository è che un'affermazione è vera solo se una macchina lo dice. I numeri del portfolio sono ricalcolati dal repository da tools/verify.mjs e la CI fallisce se uno di loro scivola. È tantissima macchina per una pagina, ed è facile pensare che la macchina sia il punto.

It is not. The point is what the machine catches. And the first thing the accessibility audit caught was this: the shared scene reader — the file that renders the nine standalone literary scenes — was throwing on load. Three of its elements carried a CSS class where the reader looked for an id, so getElementById returned null, the very next line crashed, and every one of those nine pages had been rendering an empty reader since the day it was written. Non è. Il punto è ciò che la macchina intercetta. E la prima cosa che ha intercettato l'audit di accessibilità è stata questa: il lettore di scene condiviso — il file che disegna le nove scene letterarie autonome — lanciava un errore in caricamento. Tre dei suoi elementi avevano una classe CSS dove il lettore cercava un id, quindi getElementById restituiva null, la riga dopo crashava, e ognuna di quelle nove pagine mostrava un lettore vuoto dal giorno in cui era stata scritta.

"TypeError: Cannot read properties of null (setting 'textContent')" — at shared/scene-reader.js, in a file that had been loaded by nine pages and had never once thrown in a console anyone was watching. «TypeError: Cannot read properties of null (setting 'textContent')» — in shared/scene-reader.js, in un file caricato da nove pagine che non aveva mai lanciato un errore in una console che qualcuno stesse guardando.

Why reading the code did not find it Perché leggere il codice non l'ha trovato

The bug was three characters long. It was also invisible to review, because the reader looked correct: it built the DOM, it styled it, it listened for the language toggle, and it looked like a working component in the source. The only way to see it was to run the page and look at what it actually rendered — and the pages that use it are literary scenes, where an empty stage looks like a deliberate design choice rather than a crash. Il bug era lungo tre caratteri. Era anche invisibile alla revisione, perché il lettore sembrava corretto: costruiva il DOM, lo stilava, ascoltava l'interruttore della lingua, e nel sorgente sembrava un componente funzionante. L'unico modo per vederlo era eseguire la pagina e guardare cosa avesse disegnato davvero — e le pagine che lo usano sono scene letterarie, dove una scena vuota sembra una scelta di design e non un crash.

This is the part worth generalising. The tool did not find a bug in the accessibility of the pages. It found a bug in the pages. The accessibility check was the excuse: the audit navigates to every app in the repository, and navigating is what made the crash visible. Any tool that touches every page finds the things that only appear when a page is actually loaded — and the checks you write first are almost never the ones that find them. Questa è la parte che vale la pena generalizzare. Lo strumento non ha trovato un bug di accessibilità nelle pagine. Ha trovato un bug nelle pagine. Il controllo di accessibilità era la scusa: l'audit naviga in ogni app del repository, e navigare è ciò che ha reso visibile il crash. Qualsiasi strumento che tocca ogni pagina trova le cose che compaiono solo quando una pagina viene davvero caricata — e i controlli che scrivi per primi sono quasi mai quelli che le trovano.

What the report looks like now Com'è fatto il rapporto adesso

It has 346 findings in it, and they are still there: 127 contrast problems in the games' muted text, 193 tap targets under 48px, and 26 canvas games that have no live region to announce their state. None of those are fixed yet. They are published, with the rule and the file and the line, because a report that shows nothing is a decoration and a report that shows only what has been fixed is marketing. Oggi contiene 346 rilievi, e ci sono ancora: 127 problemi di contrasto nel testo attenuato dei giochi, 193 aree touch sotto 48px e 26 giochi su canvas senza un'area live per annunciare il loro stato. Nessuno di questi è ancora sistemato. Sono pubblicati, con la regola, il file e la riga, perché un rapporto che non mostra niente è una decorazione e un rapporto che mostra solo ciò che è stato sistemato è marketing.

Read the report: the self-audit. Run the tool: node tools/audit/run.mjs. It skips cleanly when there is no browser, because a missing Chromium must never be the reason a build goes red. Leggi il rapporto: l'auto-audit. Fai girare lo strumento: node tools/audit/run.mjs. Salta in modo pulito quando non c'è un browser, perché un Chromium mancante non deve mai essere il motivo per cui una build diventa rossa.
