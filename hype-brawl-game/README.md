# HYPE BRAWL — THE LAST VIRALITY

An original 2.5D platform fighter for the browser. Everyone wants the spotlight. You take it by launching everyone else out of frame.

Built with TypeScript, Vite, Three.js and Web Audio. Characters, stages, UI, music, sound effects and models are original and generated by the project — no Nintendo characters, assets, music or interfaces are used.

### Not included (honest status)

- **Online multiplayer**: the deterministic input protocol, checksums, input history and rollback hooks exist in `src/network/`, but no server/lobby is shipped. Online is not faked with scripted opponents.
- **Tournament**: shown as a roadmap screen; the bracket is not implemented.
- **Full roster**: the 12 remaining fighters are data-scaffolded and visibly locked. They do not have real movesets and are not selectable.
- **5 stages** are locked placeholders.
- **WebGPU renderer**: WebGPU support is detected for diagnostics; the shipping renderer is WebGL2, the reliable fallback. A full WebGPU pipeline is future work.
- **GLB fighter models**: the loader pipeline is prepared in `src/fighters/visuals/glbModelLoader.ts`; the current roster uses original procedural models.
- Full rollback netcode, full tournament UI, LOD streaming and advanced animation rigging are future milestones.

## Controls

### Player 1 (keyboard)

| Action | Key |
| --- | --- |
| Move | A / D |
| Aim up / down | W / S |
| Jump / double jump | W or Space |
| Attack (direction selects tilt/aerial) | F |
| Strong attack — hold to charge, release to strike | G |
| Special (direction selects variant) | H |
| Shield / ground roll (shield + direction) / spot dodge (shield + down) / air dodge (air + shield) | J |
| Grab; while grabbing, direction + attack throws | K |
| Taunt; at 100 Hype, activates HYPE MODE | T |

### Player 2 (keyboard)

Arrows move/jump, **Enter** jump, **,** attack, **.** strong, **/** special, **;** shield, **'** grab, **\\** taunt. All bindings are remappable in Settings.

### Gamepad (standard mapping)

- Left stick / D-pad: move and aim
- A: jump · B: attack · X: strong · Y: special
- LB / LT: shield · RB: grab · RT: taunt
- Start: pause

The HUD switches a human player's control label to **PAD** automatically when gamepad input is detected.

### Touch

On coarse-pointer devices a joystick and six action buttons appear during a match: JUMP, ATK, SPEC, STRONG, SHIELD, GRAB. Desktop remains the priority.

## Gameplay systems

### Damage → knockback → ring out

There is no health bar. Each fighter accumulates damage percentage. The launch formula uses the attacker's base knockback and growth, the victim's post-hit percentage, weight, knockback resistance and DI:

```
damageTerm   = percent / 10 + (percent * damage) / 20
weightTerm   = 200 / (weight + 100)
magnitude    = ((damageTerm * weightTerm * 1.4 + 18) * growth / 100 + base)
                * hypeMultiplier * (1 - knockbackResistance)
hitstun      = floor(magnitude * 0.55) + 4
```

DI rotates the launch by up to ±18° based on stick input perpendicular to the launch angle. Values are tunable per move in `src/fighters/types.ts` / character data.

### Combat engine

- Hitboxes, hurtboxes, grabboxes and shieldboxes are separate from meshes.
- Priority-aware attack clashes: equal-priority active hitboxes cancel each other; specials beat strongs, strongs beat normals.
- Every hitbox has startup/active/recovery frames, damage, angle, base knockback, growth, hitstop, optional meteor flag and effect tag.
- Hitboxes only exist in their active windows; hit targets are recorded per hitbox so one active window cannot multi-hit accidentally.
- Shields absorb damage, drain, regenerate, stun and break.
- Hitstop freezes both fighters; hitstun disables control; DI is sampled at contact.
- Every move dataset lives with the fighter definition, not in the engine.

### Fixed timestep and determinism

- Simulation runs at **60 Hz** fixed steps; rendering interpolates and is decoupled.
- No `Math.random()` in the simulation; `Rng` (mulberry32) is seeded and included in snapshots.
- Inputs are frame-indexed. The AI is stateless and derives decisions from the simulation RNG and visible state.
- `Simulation.snapshot()` / `restore()` and `stateHash()` are tested for replay determinism.
- Renderer, UI and audio never mutate simulation state.

### Modes

- **Stock** — configurable 1–9 stocks; last fighter standing wins.
- **Time** — 1–10 minutes, most KOs wins, infinite respawns during the clock.
- **Team** — 2v2 with team colors, friendly fire off, team victory when the other team is eliminated.
- **Training** — dummy CPU, reset, damage presets, frame data, input history, infinite jumps/hype, hitbox view.
- **Spectator** — four CPUs fight autonomously; real simulation, not canned animation.
- **Tournament / Online** — roadmap screens only in this build.

### Items

All eight items spawn from the sky, fall, land and can be picked up:

HYPE BATTERY · GOLDEN MIC · SPEAKER DRONE · GLITCH CAPSULE · MEGA BURGER · ROCKET SNEAKERS · COMMENT BOMB · TURBO CAN.

Frequency is configurable: OFF / LOW / NORMAL / CHAOS.

### Stage hazards

Each stage has an environmental hazard (speaker shockwave, train burst, laser sweep). Hazards can be turned off in Setup or Settings for competitive play.

## Adding a fighter

1. Create `src/fighters/data/yourFighter.ts`. Use the data factory for normals and define four unique specials:

```ts
import { hit, standardMoves } from '../moveFactory';
import type { FighterDefinition, MoveData } from '../types';

const neutralSpecial: MoveData = {
  slot: 'neutralSpecial',
  name: 'YOUR PROJECTILE',
  kind: 'special',
  totalFrames: 32,
  hits: [],
  projectiles: [{
    atFrame: 12, offsetX: 0.9, offsetY: 1.0, vx: 0.3, vy: 0,
    gravity: 0, radius: 0.4, damage: 8, angle: 35,
    baseKnockback: 18, knockbackGrowth: 50, life: 80, visual: 'sound',
  }],
};

export const YOUR_FIGHTER: FighterDefinition = {
  id: 'your-fighter',
  name: 'YOUR FIGHTER',
  title: 'The Something',
  archetype: 'Your archetype',
  description: 'Original character description.',
  playable: true,
  modelStyle: 'nero', // or add a new builder style
  stats: { weight: 100, walkSpeed: 0.09, runSpeed: 0.16, airSpeed: 0.13,
    airAcceleration: 0.013, gravity: 0.019, jumpVelocity: 0.43,
    doubleJumpVelocity: 0.4, maxFallSpeed: 0.58, fastFallSpeed: 0.8,
    groundAcceleration: 0.02, groundFriction: 0.014, airFriction: 0.0025,
    airJumps: 1, knockbackResistance: 0, attackPower: 1, recoveryPower: 1,
    width: 0.95, height: 1.85 },
  palettes: [{ name: 'Default', skin: 0xc9835e, primary: 0xff2d95,
    secondary: 0x39f6ff, accent: 0xffd319, hair: 0x140a10, dark: 0x08030d }],
  moves: standardMoves({
    power: 1, speed: 1,
    specials: { neutralSpecial, sideSpecial, upSpecial, downSpecial },
  }),
  moveHighlights: ['Special 1', 'Special 2', 'Special 3', 'Special 4'],
  statsBars: { power: 3, speed: 3, weight: 3, recovery: 3 },
};
```

2. Add it to `PLAYABLE_FIGHTERS` in `src/fighters/roster.ts`.
3. If you want a unique silhouette, extend `modelStyle` in `types.ts` and add a branch in `fighterModels.ts`.
4. Add the required slots to `tests/roster.test.ts` automatically by keeping the same `MoveSlot` contract. Run `npm run typecheck && npm run test`.
5. Optional: place an original licensed GLB in `public/assets/characters/` and use `loadFighterAsset()`; add its license to this README.

No fighter is selectable until it has every move in the data contract; the UI only unlocks entries in `PLAYABLE_FIGHTERS`.

## Adding a stage

1. Add a `StageDefinition` in `src/stages/stageData.ts`:
   - `platforms` (ground + floating + moving platforms, with optional `moving` axis/amplitude/speed/phase)
   - `blastZones`, `spawns`, `cameraBounds`
   - `theme` colors, `music` track and optional `hazard`
2. Push it into `PLAYABLE_STAGES`; it appears automatically in Stage Select.
3. For custom set dressing, add a branch in `StageView.buildStageDecor()` using original geometry and lights. The shared platform/neon/crowd/particle system works without extra code.
4. Add a regression check in `tests/roster.test.ts` if you introduce a new invariant.

## Browser support and performance

- Prioritizes desktop Chrome/Edge/Firefox/Safari with WebGL2.
- Fixed 60 Hz simulation; render interpolation; pixel ratio capped at 2.
- Directional shadow map at 1024, pooled particles/rings, shared stage materials, frustum culling, PWA asset caching.
- Debug overlay: FPS, frame time, physics tick, draw calls, meshes, triangles, geometries, textures, pixel ratio, camera distance, estimated heap, gamepad count, WebGPU detection.
- Headless QA measured 60 FPS with 4 fighters on the Club stage; real-hardware results vary.
